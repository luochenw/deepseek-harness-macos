# Agent Note: 设置页滚动与自定义配置入口

Status: proposed — 移除原生界面对 Relay 的产品级假设，修复设置长内容不可达的问题。

## Problem

设置窗口把右侧内容直接放在固定高度的 `VStack` 中。提供方和插件分区的列表超过窗口高度后没有滚动容器，底部内容无法访问。现有输入控件仅使用与背景接近的填充色，没有明确边界，尤其在设置窗口中不容易识别为可输入字段。

模型分区还把 `relay` 和 `deepseek` 写成唯一的两个产品选项，并按该二分法决定 API Key 的环境变量。`relay` 实际上只是某些用户已有配置中的一个路由 ID；新用户和接入其他兼容端点的用户不应被要求理解或拥有它。

## Proposal

- 将设置窗口的主内容置于固定标题和底部操作栏之间的垂直 `ScrollView`，让提供方、插件和预设等所有超长内容可达。
- 强化共享 `dshField` 样式，使用与页面表面区分的填充、细描边、稳定高度和强调色，使文本字段明确呈现为可编辑控件。
- 以 Host 的 `llm.models`、`llm.providers`、`settings.describe` 和动态凭据引用作为模型/凭据的唯一来源。模型页不再显示固定的 Relay/DeepSeek 分段控件，也不直接写 API Key。
- 将用户面向的入口统一命名为“自定义配置”。已有 `relay` 路由继续作为 Host 配置 ID 兼容读取和编辑，但不再作为默认产品或专用凭据路径。
- 将通用设置 JSON 编辑器中的凭据引用改为可输入的任意环境变量名，而不是固定 Relay/DeepSeek 的选择器。

## Alternatives considered

- **只给提供方和插件各自包一层固定高度的嵌套滚动列表**：能解决两个当前列表，但会造成多层滚动和滚轮焦点争夺，也不能处理 Agent 预设等其他长内容。
- **保留 Relay 选项，只把名称换成“自定义”**：仍会在启动默认值、凭据环境变量和设置编辑器中依赖 Relay，实际行为仍不适用于没有该路由的用户。
- **删除全部已有 Relay 配置并强制迁移到新 ID**：会破坏现有用户的 Host 设置和已保存凭据；界面去品牌化即可满足需求，底层路由 ID 应保持兼容。

## Acceptance criteria

- 设置窗口的提供方和插件内容在固定窗口内可以垂直滚动，底部条始终可见。
- 文本输入和安全输入具备明显的可编辑边界；自定义配置表单保留字段标签和示例占位文本。
- 新启动的原生状态不以 `relay` 为默认提供方或模型；模型选择与凭据状态来自 Host 的实际目录。
- 用户可以从“自定义配置”创建、编辑任意 Host 支持的端点配置，并为其写入对应凭据。
- 现有 `relay` Host 路由不会被删除或改写。

## Risks

- Host 在没有任何自定义端点时只返回内置模型目录，因此模型页必须明确引导用户到自定义配置，而不是展示空白或固定假数据。
- 旧的应用偏好可能保存过 `relay` 选择；实现不依赖该偏好，并在 Host 连接后以会话/目录的真实状态为准。
