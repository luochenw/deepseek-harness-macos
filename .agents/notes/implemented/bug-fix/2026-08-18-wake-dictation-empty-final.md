# Agent Note: 唤醒听写"说完没反应" —— 三个叠加的识别层缺陷

Status: implemented — 空定稿、分段丢失、麦克风竞态三修

## Problem

唤醒后说任务，识别文字实时可见，定稿一瞬间全部消失、没有派发任何
会话、界面毫无反馈。文件诊断日志（voice-diag.log）复现出完整链路后
定位到三个叠加问题：

1. **空 isFinal 覆盖**：Apple 本地中文识别在 endAudio 后经常回一个
   `isFinal=true` 但 text 为空的最终结果，代码无条件用它覆盖累积转写
   ——整句好话被抹成空串，走"放弃"分支恢复输入框（= 用户看到的
   "文字消失"）。
2. **停顿分段丢失**：说话中停顿约 1 秒，识别器把 bestTranscription
   整个重置为新段（"帮我去找"→"国庆节…"），旧段直接丢弃。
3. **麦克风移交竞态**：唤醒常驻引擎刚拆、听写引擎立刻抢启时会拿到
   无声输入流（buffer 有帧但识别零结果，数秒后空定稿）。

## Decision

- 识别回调：非空新文本若与旧段互不为前缀且明显更短 → 判定分段重置，
  旧段计入 `committedPrefix` 累积；定稿/实时展示均为前缀+当前段。
  空结果一律不覆盖非空累积。
- 唤醒路径的听写延迟 300ms 启动，给常驻引擎释放设备留一拍。
- 顺带：唤醒+自动派发模式的听写不再流进输入框（任务去独立会话，
  输入框不该被碰）；派发失败在状态条直接可见（前台通知被系统抑制、
  未选中会话时 transcript 备注无处可写，此前失败完全静默）。
- 诊断基建保留：`voiceDiag()` 追加写 dsh 配置根的 voice-diag.log
  ——NSLog 在统一日志中检索不可靠，这条链路的问题只有文件日志
  能远程定位。

## Alternatives considered

- **只修空 isFinal（单修）**：TTS 端到端复现证明三个问题独立存在，
  单修任何一个仍复现"说完没反应"或"半句丢失"。
- **共享一个 AVAudioEngine 替代延迟启动**：更彻底但重构面大（两个
  识别引擎的 tap 生命周期合并）；300ms 延迟实测稳定，先用。
- **用统一日志（NSLog/os_log）做诊断**：实测 log show 检索不到本
  app 的 NSLog 输出（多次采样为空），放弃。

## Consequences

- 端到端验证通过：唤醒→带停顿的整句→静音定稿→派发建会话（TTS 自测
  与用户真人测试各两轮，diag 日志留档）。
- 分段重置启发式（互非前缀且更短）理论上可能把"整句重写"误判为
  分段——实测未出现；若出现表现为文字重复，可再收紧。
