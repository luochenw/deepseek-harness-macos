# Agent Note: 打开会话内容乱跳、滚到底部时展开的指令被折叠、展开后卡顿

Status: implemented — 五个独立原因都已修复，用户确认「不抖了」「不卡了」

## Problem

v0.6.0 之后用户连续报告了三个现象：

1. 鼠标滚到最底部时，展开的指令组会被折叠。
2. 打开已有会话时右侧内容乱跳，要过一会才停。真实日志里内容高度从 61347 一下塌到 797，再分几次长回来。
3. 展开指令以后会卡，只能展开一组，第二组展不开。

这些现象看起来是一件事，实际是几个互不相关的原因叠在一起。

## Decision

- **展开状态不放在行视图里**：`LazyVStack` 把滚出屏幕的行卸载后，`@State` 就丢了。展开状态改存到 `DSHToolGroupExpansionStore`，按行 id 保存。
- **较短的 follow 快照只合并，不替换**：`session/follow` 的首帧只带一条消息，晚于完整历史到达时，会把已显示的历史覆盖掉，这就是 61347 塌到 797 的原因。`DSHHistoryPageMerge.applyFollowSnapshot` 现在用 `mergeTail` 合并。
- **跟随尾部限频**：内容不变时也有每秒几十次滚动请求。现在最多 0.1 秒一次，已经贴底时不再发。
- **指令分类加缓存**：`DSHCommandMemo` 缓存摘要和写文件判断，上限 2048 条，已展开的行不再反复重新分类。
- **行版本只看长度和末尾**：`rowVersion` 哈希 UTF-8 长度和最后 64 字节，不再遍历全文。
- **发布版开启优化**：之前每个发布版都没有 `-O`。`build-macos-app.sh` 和 `refresh-macos-app.sh` 都改成 `-O -whole-module-optimization`。

## Alternatives considered

- **把 `LazyVStack` 换成 `VStack` 来保住 `@State`**：长会话要一次布局全部行，首屏会重新变慢。
- **保持替换，等完整历史再补回来**：这正是抖动本身。
- **认为是整表换 id**：回放证明 id 没有变化，假设不成立。
- **认为是缓存键的哈希太慢**：`sample` 显示热点不在这里，假设不成立。
- **只降低滚动频率，不加贴底判断**：内容不变时仍然会空转。

## Consequences

- 用户确认打开会话「不抖了」，展开「不卡了」。
- 一分半内的滚动请求从每秒 41 次降到总共 12 次。
- 优化后可执行文件从 21.7MB 降到 12.1MB。
- 打开优化以后才看清剩下的开销是运行动画，见 [运行动画](2026-11-02-running-animations-on-core-animation.md)。
- 「第二组展不开」已有单测，真实 App 里还没有得到用户的明确确认。
- `unexplained-jump` 这类滚动位置读到 0 又回来的记录仍未解释，目前没有观察到用户可见的影响。
