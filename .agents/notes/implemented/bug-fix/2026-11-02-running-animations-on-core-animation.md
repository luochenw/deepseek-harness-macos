# Agent Note: 运行动画占满主线程，打开运行中的会话会掉帧

Status: implemented — 运行线、运行小条和等待波浪改由 Core Animation 驱动，外观不变；亮屏测量已通过，手感待用户确认

## Problem

用户反馈：「不卡了，但是还有点掉帧」（2026-11-01）。

打开优化编译（`-O`）以后，长任务本身已经不卡，但只要有会话在运行，App 就持续占 CPU。用一个只跑 `sleep 90` 的会话对比：优化版平均 34.2%，把循环动画全部关掉是 0.0%。`sample` 显示主线程一直在 `UpdateCycle → CA commit → 重绘文字`。

原因：运行线和运行小条用 SwiftUI 的 `repeatForever`，等待波浪用 `TimelineView`。这两种写法都由 SwiftUI 在主线程逐帧驱动，窗口越大，每帧要提交的内容越多。一条 1.2pt 的线就能占掉主线程三分之一，滚动和流式文字只能抢剩下的时间。

等待波浪只有 20 帧，曾被当作不重要。放进同一个测试窗口才发现它和运行线一样贵：旧运行线 3.0%，波浪 3.5%。

## Decision

三个动画都改成图层动画，由系统渲染进程执行，不再占用 App 主线程：

- `DSHActivityLine`：`CABasicAnimation` 平移 `position.x`，时长 1.8 秒、缓入缓出、往返循环。出现时 0.18 秒的展开也保留。
- `DSHRunningBars`：三根小条各一组缩放和透明度动画，时长 0.58 秒，依次错开 0.1 秒。
- `DSHRunningWhaleIcon`（新文件）：替换 `TimelineView`。每层浪画成比画布宽一个波长的长条，匀速平移一个波长后循环，这和相位走满一圈的画面完全相同；鲸的跃身预先算好 64 个关键帧。波浪的基线、振幅、速度和初相提到 `SeaArt.Wave`，海景和运行图标共用一份，形状仍然用 `WaveBand`、`WhaleBody`、`WhaleFluke`、`WhaleMouth` 生成。

共同的约定：对外接口不变；视图不在窗口里、任务结束或开启“减弱动态效果”时都移除动画；颜色随外观重新解析；不响应点击。

等待波浪以前不看“减弱动态效果”，现在和另外两个动画一致，开启后显示静止画面。

## Alternatives considered

- **关掉运行线或改成静止标记**：用户要的就是这条会动的线。
- **降低帧率**：只能减少，不能消除；20 帧的波浪已经和 60 帧的线一样贵。
- **把动画放进单独的 `NSHostingView`**：仍在主线程更新，只是把重绘范围缩小。
- **波浪用形状关键帧逐帧变形**：渲染进程每帧都要重新铺路径；三层浪都是同一个余弦，平移就够了，一条动画就能完成。
- **预渲染成序列帧**：三层浪的公共周期是 62.8 秒，20 帧要存 1256 张，而且放大后会糊。
- **只改运行线**：会把开销原样留在打开的运行会话里，正是用户看到掉帧的地方。

## Consequences

测量结果：

| 场景 | 改之前 | 改之后 |
| --- | --- | --- |
| 真实 App，运行线（`sleep` 会话） | 34.2% | 0.0%（最高 1.7%） |
| 测试窗口，运行线 | 3.0% | 0.0% |
| 测试窗口，等待波浪 | 3.5%–5.3% | 0.0% |

- 外观用像素对比：4 个时间点上，新波浪和原来的 `SeaWhaleScene` 平均差异不到 1/255，差异明显的像素最多 0.28%。
- 上表的数字都是在屏幕关闭且已锁屏时测的，前后状态相同，可以互相比较。
- 亮屏补测（2026-11-02 01:01，已解锁）：有运行会话时 App 平均 0.5%，最高 2.4%，空闲时 0.6%；系统渲染进程运行时 36.8%，空闲时 41.6%，没有升高，开销没有转移过去。渲染进程的绝对值主要来自屏幕上的其他内容。亮屏下没有测旧版，所以没有亮屏的前后对比。手感要用户自己看。
- 真实 App 里没有测到等待波浪：它只在打开的运行会话里显示，无人操作时打不开会话，所以只有测试窗口的数字。
- 图层动画不再经过 SwiftUI，不能再用 `repeatForever` 的字符串检查，`scripts/test-design-system.sh` 改查 `shuttle.repeatCount`；单测改为检查动画在窗口内外的增减，运行线还检查了图层确实在移动。
- 其他循环动画（悬浮圈 `FloatingBubble`）这次没有动，它只在语音时显示。
