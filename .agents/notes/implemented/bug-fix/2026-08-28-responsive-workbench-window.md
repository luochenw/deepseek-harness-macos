# Agent Note: 窄窗口下工作台挤压侧栏与输入框

Status: implemented — 窄窗口改用紧凑三栏，窗口不再裁切侧栏和 Composer

## Problem

主窗口根视图声明 1180pt 最小宽度，但没有把该尺寸传递为原生窗口的 resize
约束。macOS 恢复旧窗口尺寸或进入窄分屏时，窗口仍可能小于 1180pt。

与此同时，左侧栏固定 290pt，工作台布局又要求对话至少 500pt、工作台至少
360pt，加上拖拽条后总需求超过窄窗口。SwiftUI 会保留这些不可压缩宽度并裁切
左侧内容，结果表现为侧栏压到输入框上，甚至大部分侧栏被推出窗口。

## Decision

- 默认窗口保持 1180×760pt；将原生窗口最小内容尺寸调整为可实际适配的
  1000×680pt，并通过 `windowResizability(.contentMinSize)` 传递给 NSWindow。
- 主窗口低于 1180pt 时把侧栏从 290pt 收紧到 260pt。
- 工作台在紧凑宽度下把对话/工作台最小宽度调整为 420/300pt；仍放不下时，
  只暂时隐藏工作台视图，保留 `showDetails` 和标签状态，窗口重新变宽后恢复。
- Composer 根据实际会话列宽度切换底部控件布局：窄列把模型选择单独放一行，
  常用工具与停止/插话/排队操作放在下一行，避免运行态控件撑破会话列。
- 会话列裁剪越界绘制，确保任一内部控件的固有尺寸都不能覆盖侧栏或工作台。
- 用纯布局测试验证各栏总宽不超过容器，并新增 1024×736 整窗快照覆盖用户截图
  对应的窄窗口、运行态长模型名和完整权限菜单场景。

## Alternatives considered

- **只把窗口最小宽度提高并禁止窄分屏。** 不选：能防止裁切，但会失去较小屏幕
  和 Split View 的可用性。
- **始终把工作台覆盖在对话上。** 不选：这会把当前的并排工作流变成遮挡式面板，
  也会再次压住 Composer。
- **只给 HStack 增加 layoutPriority。** 不选：三个不可压缩最小宽度的总和仍然
  大于容器，优先级只能改变被裁切对象，不能消除溢出。

## Consequences

- 1024×736 窗口中侧栏、对话和工作台都在窗口范围内，Composer 不被覆盖；
  新增真实整窗快照固定运行态的最宽控件组合。
- 1000pt 最小窗口中三栏仍完整并排；异常恢复到更窄尺寸时，工作台状态保留
  但不参与布局。
- 1180pt 及以上维持现有 290pt 侧栏、500pt 对话和至少 360pt 工作台。
- 现有工作台标签、拖拽宽度、亮/暗色样式和圆角令牌不改变。

## Residual risks

- 断点附近切换侧栏宽度会产生轻微布局变化；应保持无动画，避免视觉抖动。
- 紧凑工作台的正文更窄，标签栏必须继续允许横向滚动。
