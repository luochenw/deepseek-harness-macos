# Agent Note: 转录末尾行——跟随滚动锚点 + 运行动画/静态落款二态

Status: implemented

## Problem

- 回答过程中会话视图不跟到最底：三处 `scrollTo` 全部锚在**最后一条消息**的 id 上，而运行动画（波浪图标）是消息之后一个独立 id 的行——跟随滚动永远停在它上面一行，动画整轮被裁在视口下方，用户看不到。
- 波浪动画只在「发送 → 首 token」的窗口显示（条件含 `messages.last?.text.isEmpty`），推理/工具阶段一过就消失；轮次结束后转录末尾没有任何收尾标记。

## Decision

- 转录非空时**始终存在一个末尾行**，二态共用一个 id（`transcript-tail`）：运行中 = 整轮持续的波浪/月亮动画（同时兼任等首 token 的填充），结束后 = 冻结在月亮顶点的静态图标（`WaveIconArt(t: 2.05)`，75% 不透明度），作为"回答完成"的落款——对应 Claude Code 回答末尾的 ⏺ 标记。
- 动画本体抽成 `WaveIconArt(t:)` 单帧视图，`WaitingWaveIndicator`（TimelineView 驱动）和 `TranscriptEndMarker`（定格帧）共用，图标绘制只有一份。
- 跟随滚动（消息变化、切会话、回到最新按钮）一律锚 `transcript-tail`；另补 `isRunning` 翻转时的一次跟随（排队消息触发的开跑可能不带新消息）。

## Alternatives considered

- **把动画行并进最后一条消息的 VStack**（共用消息 id，不用改锚点）——不选：动画不属于任何一条消息，塞进消息行会让 fold/分组逻辑和消息 Equatable 语义变脏；末尾行独立 + 改锚点是最小改动。
- **结束后彻底移除末尾行**（维持原状，只修滚动）——不选：用户明确要结束后的静态落款；而且末尾行常驻让锚点 id 恒存在，三处 scrollTo 不用再按状态挑目标。
- **动画维持"仅等首 token"窗口**——不选：用户的诉求就是"回答过程中看到执行中的动画"；cc/codex 也是整轮显示 spinner。26px 小图标在流式文本下方不构成干扰。

## Consequences

- 运行中视口底部始终是滚动的波浪动画（跟随未被用户上滚打断时）；结束后原位淡为静态图标，历史会话和子代理转录的末尾也带落款。
- 空转录（空态页）无末尾行，滚动调用前判空。
- `WaveIconArt` 改颜色/构图时动画与落款自动同步。
