# Agent Note: 设置页滚动与自定义配置入口

Status: implemented — 设置窗口改为可滚动的原生配置界面，Relay 不再是产品级必需入口。

## Problem

设置窗口把右侧内容直接放在固定高度的 `VStack` 中。提供方和插件分区的列表超过窗口高度后没有滚动容器，底部内容无法访问。现有输入控件仅使用与背景接近的填充色，没有明确边界，尤其在设置窗口中不容易识别为可输入字段。

模型分区还把 `relay` 和 `deepseek` 写成唯一的两个产品选项，并按该二分法决定 API Key 的环境变量。`relay` 实际上只是某些用户已有配置中的一个路由 ID；新用户和接入其他兼容端点的用户不应被要求理解或拥有它。

## Decision

- 设置窗口的标题和底部操作栏固定，中间使用始终显示滚动指示器的垂直 `ScrollView`。提供方、插件、凭据和预设等长内容共享这一层滚动，避免嵌套滚动。
- `dshField` 使用独立填充色、一像素描边和稳定最小高度，让文本和安全输入控件在任何设置页中都明确可编辑。
- 模型与凭据状态只从 Host 的 `llm.models`、`llm.providers`、`settings.describe` 和递归解析的 `apiKeyEnv` 引用获取。模型页不再直接写入固定环境变量。
- 用户入口统一命名为“自定义配置”。旧路由 ID `relay` 在列表中按“自定义配置”显示并保持可编辑，底层 Host 配置与已保存凭据不被迁移或删除。
- 通用 JSON 设置编辑器的凭据引用改为可输入任意环境变量名，打开已有命名空间时优先预填该命名空间声明的第一个引用。

## Alternatives considered

- **只给提供方和插件各自包一层固定高度的嵌套滚动列表**：能解决两个当前列表，但会造成多层滚动和滚轮焦点争夺，也不能处理 Agent 预设等其他长内容。
- **保留 Relay 选项，只把名称换成“自定义”**：仍会在启动默认值、凭据环境变量和设置编辑器中依赖 Relay，实际行为仍不适用于没有该路由的用户。
- **删除全部已有 Relay 配置并强制迁移到新 ID**：会破坏现有用户的 Host 设置和已保存凭据；界面去品牌化即可满足需求，底层路由 ID 应保持兼容。

## Consequences

- 新安装不会从原生 UI 默认选择 `relay` 或 `gpt-5.6-terra`，也不会生成 Relay 专用默认路由；Host 连接后以当前会话和目录的真实选择为准。
- 如果旧应用偏好指向不再存在的路由，模型目录刷新会清除该本地选择，下一次新会话保留 Host 默认模型而不是发送无效选择。
- Host 没有任何自定义端点时，模型页会保留真实的内置目录并提供“管理自定义配置”入口，不再展示固定假数据。
- `scripts/test-settings-ui.sh` 被并入 `scripts/test-macos-native.sh`，约束独立设置视图、滚动指示器、可见输入边界和 Relay 专用入口不会回归。
- 可视自动化在当前桌面会话未能返回原生 accessibility tree；验证覆盖 Swift 类型检查、完整 App 构建、签名/Info.plist 检查、Host 只读冒烟测试和结构回归脚本。实际窗口仍由打包 App 启动并可手动检查。
