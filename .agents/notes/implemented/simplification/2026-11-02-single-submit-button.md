# Agent Note: 输入框只留一个按钮，随状态在发送和停止之间切换

Status: implemented — 空闲时是发送；运行中草稿为空时是停止，有内容时是发送；Esc 随时停止

## Problem

用户反馈：「为什么有两个按钮，一个就行啊，状态切换」，随后补充：「你可以在加一个状态啊，如果有输入就显示发送，但是按esc也可以停止」（2026-11-02）。

运行中，输入框右侧同时出现停止按钮和“直接发送到当前轮”按钮；在可续聊子会话里，或者已有排队消息时，还会再多一个排队按钮。发送按钮在空草稿时是禁用的半透明状态，紧挨着停止按钮，看起来像是“停止按钮按不动”。用户希望同一个位置只有一个按钮，按状态切换。

## Decision

- 同一个位置只有一个按钮，统一用主按钮样式：
  - 空闲：发送。
  - 运行中、草稿为空：停止。
  - 运行中、草稿有文字或图片：发送，走和回车相同的路径（`submitBusyComposer`），按“通用 → 已有队列时回车”的设置插话或排队。
- 运行中显示停止还是发送，只看草稿有没有内容（`runningComposerShowsSend`），不看提交是否正在进行。正在发送时，发送按钮变灰不可点，不会在光标下突然变成停止，避免误停。
- 选了 Agent Profile 时运行中不能派发 Batch，所以按钮保持停止。
- Esc 随时停止本轮，不管按钮此刻显示的是什么。⌘回车仍用另一种方式发送。
- 语音的插话、排队路由（`steerDraft` / `queueDraft`）不变；排队消息的徽标和队列面板照常显示。

## Alternatives considered

- **运行中只显示停止，发消息只走键盘**：先这样做过，用户随后要求“有输入就显示发送”。只靠键盘时，鼠标用户看不出运行中还能补充消息。
- **保留独立的排队按钮**：不选。用户要求只留一个按钮；排队可以通过回车设置或 ⌘回车完成。
- **按 `canSubmitRunningDraft` 决定显示哪个按钮**：不选。它在发送途中会暂时为假，按钮会在点击后一瞬间变成停止，连点就可能误停。
- **停止用次级按钮样式**：不选。它占的是发送按钮的位置，用同一种主按钮样式才像是同一个按钮切换状态。

## Consequences

- 运行中打了字又想停止，要按 Esc，或者先清空草稿。按钮的提示文字写明了“Esc 停止本轮”。
- 推翻了 `bug-fix/2026-10-23-direct-running-send-without-queue.md` 中“运行中有独立的直接发送按钮和排队按钮”这一条；那份记录里空队列直接插话、队列界面防抖的规则仍然有效。
- `scripts/test-permission-composer-ui.sh` 不再要求运行中有独立的插话和排队按钮，改为要求运行中有停止，并且发送走 `submitBusyComposer`。
- 测试：`macos/DSHTests/DSHPermissionAndSubmissionTests.swift`（"Running composer shows Send only once the draft has content"）。
