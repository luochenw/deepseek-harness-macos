# Agent Note: 语音派活 —— 按 App 前后台路由唤醒词任务

Status: implemented — 前台进入当前会话，后台派发独立会话

## Problem

唤醒词定稿后如果始终走 composer 的通用提交路径，App 在后台时会把任务
塞进碰巧打开的会话；如果始终派发独立会话，用户正看着对话时又无法自然地
继续当前上下文。路由需要在听写开始时确定，并且不能因为听写过程中窗口
焦点变化而翻转。

## Decision

- `VoiceController.startListening(viaWake:)` 在听写开始时快照 `VoiceRoute`：
  - App 处于前台且 key window 是普通窗口时使用 `dialog`；
  - App 在后台、没有 key window，或焦点在悬浮 `NSPanel` 时使用
    `background`。
- `dialog` 路由会请求 Composer 获得焦点，定稿文本进入当前输入框。唤醒自动
  发送开启时，空闲会话直接发送，运行中的会话进入 Host queue；手动点击
  麦克风仍只填入，不自动发送。
- Composer 同时快照听写开始时的会话/子代理目标；若用户在说话期间切换
  上下文，最终文本只保留在输入框，不自动发送到后来切换到的会话。
- `background` 路由在唤醒自动发送开启时调用 `dispatchVoiceTask`：
  1. **工作区判定 v1（本地）**：任务文本里出现某个已引入工作区的名字
     （不区分大小写包含匹配）→ 派到该工作区；否则当前工作区。
  2. 在判定的 cwd 创建**独立新会话**（沿用当前 preset/模型/推理档），
     注入任务文本，后台运行 —— **不切换界面、不占用输入框**（听写期间
     流入输入框的实时文字在派发时恢复原状）。
  3. 完成提醒：拦截派发会话的 `turn/end` mux 事件（非当前会话的事件本来
     被丢弃）→ 系统通知 + Dock 角标；审批/提问本就有全局通知帧，无需
     另做。派发失败也发通知。
- "唤醒自动发送"关闭时，无论路由快照为何都只把最终文本保留到 Composer；
  后台听写不会因为不派发而丢失。取消类指令仍整段放弃。

## Alternatives considered

- **单独调一次 LLM 判定工作区**：会加秒级延迟且要多养一条轻量路由。
  实际采用"执行者自判"：派发的任务附带文件夹清单（名字+绝对路径），
  执行任务的模型自己决定去哪个目录干活——判定与执行合一，零额外调用。
  局限：会话的名义 cwd 仍按第一级判定落位（侧栏分组按它算）。
- **唤醒任务始终进当前会话。** 放弃：App 在后台时行为仍取决于碰巧打开的
  会话，无法静默派活。
- **唤醒任务始终进独立会话。** 放弃：用户正看着当前对话时无法用语音自然
  续接上下文。
- **定稿时再读取前后台状态。** 放弃：听写期间切换窗口会让任务目的地在
  用户说话后改变；开始时快照更可预测。
- **派发后自动切换到新会话。** 放弃：与后台静默执行矛盾。

## Consequences

- 派活不依赖工作区：未选工作区或目录已删除时回退 Host 默认目录建会话
  （cwd=nil 合法；带失效路径会让 session.create 直接失败，表现为"说完
  没反应"），反馈文案用「默认目录」而非工作区占位词。

- 前台唤醒 = 当前对话输入/发送；后台唤醒 = 独立派活，路由边界明确。
- 听写期间切换会话不会把结果误发到新的目标。
- 关闭自动发送后，前后台听写结果都会留在 Composer，等待用户确认。
- 派发会话与普通会话在列表中无差别显示（按工作区分组、running 呼吸点）。
- 完成通知点击只激活 App（NativeAlerts 现状），未深链到具体会话——
  后续可带 sessionId 直达。
