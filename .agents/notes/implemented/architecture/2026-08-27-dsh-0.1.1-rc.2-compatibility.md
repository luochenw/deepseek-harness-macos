# Agent Note: DSH 0.1.1-rc.2 compatibility

Status: implemented — superseded by the single-runtime build decision on 2026-08-28

> Superseded by
> [2026-08-28-single-latest-dsh-runtime.md](2026-08-28-single-latest-dsh-runtime.md):
> builds now package only the repository-pinned npm latest runtime and reject
> rc.6/rc.7.

## Problem

The app and CI currently build against `@deepseek-ai/dsh` `0.1.0-rc.7`.
The latest upstream release is `0.1.1-rc.2`, whose bundled Host now opens the
browser by default, whose session-projection registration contract changed
from `schema` / `view` to `stateSchema` / `wire`, and whose continuable
subagent implementation has diverged from the source anchors used by the
Agent Platform runtime patch.

The existing patch is deliberately version-gated, so a latest-version build
currently fails before producing an app. Blindly extending the allowlist would
also be unsafe: upstream now supplies reserved child identities and exact
selected-child draining itself, while the native Agent Platform still needs
out-of-tree cwd, preset, sandbox, message-id idempotency, managed-follow-up,
projection-event, and plugin-mounting extensions.

## Decision

- CI is pinned to `@deepseek-ai/dsh@0.1.1-rc.2`, and the runtime patch recognizes
  that exact release.
- The existing `0.1.0-rc.6` / `0.1.0-rc.7` patch path remains for local
  backward compatibility, with version-specific branches for behavior now
  supplied upstream. The patch validates the versions of `dsh-subagent`,
  `dsh-session`, and `dsh-web-app` as well as the top-level package before
  editing compiled source.
- Upstream `childId` support and `drainContinuableChildren` are used on the new
  release instead of re-adding equivalent private methods.
- The bundled Agent Platform projection supplies both the legacy
  `schema` / `view` fields and the new `stateSchema` / `wire` fields.
- The native Host launcher and smoke launcher add `--no-open` for
  `0.1.1-rc.2`; older supported releases keep their accepted argument set.
- The Swift `host.describe` model accepts the additive `home` field and the
  contract's optional provider/model fields.
- Runtime tests exercise the synthetic legacy fixture, the actual installed
  DSH package, repeated patching, dependency-version mismatch rejection, both
  child-disposal paths, and a cold-child close.

## Alternatives considered

- **Drop support for rc.6/rc.7 immediately.** Rejected because developers with
  the previously documented global runtime would lose local builds for no
  protocol reason; a small version branch keeps that compatibility explicit.
- **Apply the old transform unchanged to rc.2.** Rejected because upstream now
  owns child-id reservation and exact child draining, and several compiled
  anchors changed. Re-patching those areas would duplicate behavior and make
  future upgrades harder.
- **Remove all runtime patching and disable the Agent Platform.** Rejected
  because the native product would lose durable isolated DSH workers, retry
  idempotency, and its persisted Batch projection.

## Consequences

- The patch still depends on compiled upstream source anchors, but both the
  top-level package and each modified dependency are exact-version checked.
- Supporting legacy and current runtime shapes adds explicit branching until
  rc.6/rc.7 support is intentionally retired.
- Verification on August 27, 2026 passed:
  - native contract and UI checks;
  - 85 Swift unit tests;
  - 95 Agent Platform Node tests;
  - real-package patching and idempotency against `0.1.1-rc.2`;
  - complete app build and packaged Host smoke for `0.1.1-rc.2`;
  - backward-compatible app build and packaged Host smoke for `0.1.0-rc.7`;
  - plist lint, strict code-sign verification, and npm peer dependency checks.
